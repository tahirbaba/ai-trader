# ADR-002: Trade Cap Semantics

**Status:** Draft (pending owner decision)

**Date:** 2026-10-23

---

## Context

BUILD_PLAN.md states "USD 1-2 per trade" as a hard constraint. This is ambiguous — it could mean the maximum margin deposited, the maximum notional traded, or the maximum possible loss. The interpretation has significant consequences for which symbols are actually tradable at the configured leverage cap.

---

## Three Interpretations

| Interpretation | What it means | Pro | Con |
|---|---|---|---|
| A: Max notional | Total trade size ≤ $2 | Simple, clear cap on exposure | At 1x leverage, $2 notional → stop must be 50% to lose $1; almost no stop is valid. At $2 notional, BTC minimum lot ($60) is 30x too large. |
| B: Max margin deposited | Collateral posted ≤ $2; notional = margin × leverage ≤ $6 at 3x | Reasonable with low leverage; maps to exchange margin field | At 3x, notional is $6; with BTC at ~$60k, min lot is 0.001 BTC = $60 — still not tradable. Only works for low-price assets. |
| C: Max loss per trade (incl. fees + slippage) | Loss-at-stop ≤ $1; margin ≤ $2; notional = whatever exchange minimum forces, if and only if loss-at-stop ≤ $1 | Directly caps real money risk; allows the exchange minimum to drive notional while the stop size controls loss | Requires careful per-trade sizing math; some symbols still untradable if min notional forces a loss > $1 even with the tightest valid stop |

---

## Selected Interpretation (Default from BUILD_PLAN.md Phase 5)

**Option C + B combined:**

- `max_margin_per_trade_usd = 2.0` — hard cap on collateral posted
- `max_loss_per_trade_usd = 1.0` — hard cap on loss if stop is hit, INCLUDING round-trip fees and slippage buffer

Notional is derived from exchange minimum requirements. A symbol is only tradable if:
1. `min_notional_usd <= max_margin_per_trade_usd × max_leverage` (notional fits within $6.00 at 3x)
2. `loss_at_stop_usd (with fees + slippage) <= max_loss_per_trade_usd`
3. Liquidation distance >= `liq_buffer_multiple × stop_distance`

---

## Implication for Tradability (max_leverage = 3, max_margin = $2.00)

`max_notional_allowed = $2.00 × 3 = $6.00`

| Symbol | Approx Price | Typical Min Lot | Min Notional | Required Leverage | Tradable at 3x? |
|---|---|---|---|---|---|
| BTC | ~$60,000 | 0.001 BTC | ~$60 | 60/2 = **30x** | **NO** — 30x >> 3x cap |
| ETH | ~$3,000 | 0.01 ETH | ~$30 | 30/2 = **15x** | **NO** — 15x >> 3x cap |
| SOL | ~$150 | 0.1 SOL | ~$15 | 15/2 = **7.5x** | **NO** — 7.5x > 3x cap |
| XRP | ~$0.60 | 10 XRP | ~$6 | 6/2 = **3x** | **Borderline** — exactly at cap; stop must fit within ~$0.17 |
| DOGE | ~$0.12 | 10 DOGE | ~$1.2 | 1.2/2 = **0.6x** | **YES** — margin < $2, tradable if stop fits |

*Note: actual values come from `docs/specs/phase0-feasibility.md` — the above are estimates for illustration.*

The feasibility script (`scripts/feasibility.py`) computes exact numbers per exchange per symbol using live public data. The owner must read `docs/specs/phase0-feasibility.md` before choosing symbols.

---

## Options for the Owner if No Symbol is Tradable

1. **Raise `max_margin_per_trade_usd` to $5–10** — Still very small; raises max_notional to $15–30 at 3x; recommended path if more symbols are needed.
2. **Raise `max_leverage` to 5–10** — Increases liquidation risk significantly; not recommended unless the owner fully understands the liquidation math.
3. **Trade spot only** — No leverage, no liquidation risk; lower reward but safer for low capital. Requires a different Exchange Adapter mode.
4. **Use a different exchange with smaller minimums** — Some exchanges (e.g., Bybit for certain pairs) have lower min notional. Check the feasibility report.
5. **Accept that only low-price assets (DOGE, XRP, similar) are tradable at this cap** — The system is designed to reject untradable symbols at the Risk Gate; this is the correct behavior.

---

## Consequences

- `config/risk.yaml` defaults are set to the "C + B combined" interpretation. The Risk Gate enforces all three conditions independently.
- If the owner raises the cap, they must edit `config/risk.yaml` and commit the change manually (Claude Code cannot edit that file).
- The feasibility report is the authoritative source for which symbols are tradable; do not guess.
- Any cap change restarts a paper validation period before live trading.

---

## Owner Decision Required

1. Read `docs/specs/phase0-feasibility.md` (produced by the Phase 0 feasibility script).
2. Confirm: are there any tradable symbols at the current $2 cap + 3x leverage, or do you need to raise the cap?
3. If raising: specify new `max_margin_per_trade_usd` and/or `max_leverage` values.
4. Specify which symbols you want to trade. The system will only approve symbols in `allowed_symbols` (config) that pass the feasibility math.
