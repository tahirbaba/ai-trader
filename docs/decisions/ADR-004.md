# ADR-004: TradingView Usage

**Status:** Draft (pending owner decision)

**Date:** 2026-10-23

---

## Context

TradingView is the industry standard charting platform and can send webhook alerts from Pine Script strategies. The system needs a chart dashboard for monitoring and potentially a way to ingest TradingView-based signals. The options range from free open-source charting to paid webhook integrations.

---

## Options

### Option (a): Lightweight Charts Dashboard Only — RECOMMENDED

Use TradingView's open-source [Lightweight Charts](https://github.com/tradingview/lightweight-charts) library (Apache-2.0 license) for the local read-only dashboard.

**What it does:**
- Renders OHLCV candles, entry/exit markers, SL/TP lines, LessonFilter/RiskGate block events
- Data comes from our own DSOR (not from TradingView's servers)
- Displays equity curve, trades table, LLM costs

**Cost:** Free (open source)

**Requirements:**
- No TradingView account needed
- No API calls to TradingView servers
- Attribution required: keep "Powered by TradingView" per the Apache-2.0 license terms

**Verdict:** Recommended. Start here. Every deployment uses this.

---

### Option (b): + TradingView Webhook Alerts as Optional Signals

TradingView Pine Script strategies/indicators send alerts to our FastAPI webhook endpoint. This is an **additive** option on top of (a).

**What it does:**
- Pine Script alerts fire → TradingView sends HTTP POST to our `/webhooks/tradingview` endpoint
- Our server validates, deduplicates, and stores the alert in the `tv_alerts` table
- Optionally triggers a brain cycle (the `TradeCycleOrchestrator` decides what to do)
- The LLM sees the alert as one labeled input in the FeaturePack — it is treated as a signal, not as a command

**Security requirements (mandatory if this option is chosen):**
- Shared secret inside the JSON body (TradingView cannot send custom headers), compared in constant time
- Source IP allowlist (TradingView's published webhook IP ranges — verify current list from TradingView docs)
- HTTPS only (ports 80/443 behind Caddy reverse proxy)
- Rate limiting per IP
- Deduplication by hash (same alert twice = ignored)
- Strict Pydantic schema: `{secret, alert_name, symbol, timeframe, signal, price, time}`; unknown fields dropped
- Symbol must be in `allowed_symbols`
- Alerts older than `tv_alert_max_age_seconds` are ignored
- Feature-flagged: `feature_flags.tradingview_webhook: false` in `config/app.yaml` (default off)
- Pine Script sources live in `/pine` so alert logic is versioned and reviewable

**Cost:** TradingView Pro plan required ($14.95/month as of 2025 — verify current pricing). Free and Essential plans do not support webhook deliveries.

**Infrastructure:** Requires a public domain/subdomain, HTTPS certificate (Caddy handles this), and the VPS with a static IP.

**Critical invariant:** Webhook alerts NEVER place orders. The only path to an order is: `Decision → LessonFilter → RiskGate → Executor`. A TradingView alert can only create a `tv_alerts` row and optionally fire a brain trigger. This is enforced in the `TradeCycleOrchestrator` and tested in the webhook test suite.

---

### Option (c): REJECTED — Scraping TradingView or Unofficial APIs

Scraping TradingView's website or using unofficial/undocumented TradingView APIs.

**Rejected because:**
- TradingView Terms of Service violation
- Unstable: unofficial APIs break without notice
- Legal risk: potential account ban + legal action
- No reproducible, auditable data

---

### Option (d): REJECTED — Webhook → Direct Order Path

Any architecture where a TradingView webhook can directly place an order without passing through the `Decision → LessonFilter → RiskGate → Executor` pipeline.

**Rejected because:**
- Violates the core architectural invariant
- TradingView alert text is untrusted external data
- Bypasses the Risk Gate — a single compromised webhook secret could cause uncontrolled trading
- Violates BUILD_PLAN.md hard rules

---

## Recommendation

**Start with Option (a) only.** The Lightweight Charts dashboard is free, requires no TradingView account, and provides all the monitoring capability needed for Phases 0–10.

**Add Option (b) only if:**
1. The system is running stably on paper/live (Phase 10+ complete)
2. The owner has an active TradingView paid plan with webhook delivery
3. A specific Pine Script signal has been identified that adds value beyond the code-based confluence score
4. The webhook security checklist above has been fully implemented and tested

---

## Consequences

- Phase 9 dashboard uses Lightweight Charts (option a). Attribution "Powered by TradingView" must appear in the UI.
- Phase 2 webhook receiver is implemented but feature-flagged off by default. It is never enabled without the security checklist passing.
- Pine Script sources, if any, go in `/pine` directory and go through PR review before use.
- `feature_flags.tradingview_webhook` in `config/app.yaml` controls whether the webhook endpoint is active. Default: `false`.
