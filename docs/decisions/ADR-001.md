# ADR-001: Exchange Selection Criteria

**Status:** Draft (pending Phase 0 feasibility results and owner decision)

**Date:** 2026-10-23

---

## Context

The AI Trader needs a crypto exchange to trade USDT perpetual futures. The owner resides in Pakistan (PK) and/or UAE. The exchange must support small trade sizes ($1-6 notional at the configured leverage cap), provide a testnet/demo environment, support exchange-side SL/TP attached to entries, and have a retail-accessible order placement API.

Key constraints from BUILD_PLAN.md:
- One-way position mode (hedge mode forbidden)
- Isolated margin (cross margin forbidden)
- Reduce-only orders required
- Exchange-side SL/TP (attached to entry, triggered on mark price) — mandatory so protection survives app crashes
- API order placement must actually work for retail accounts (not restricted/under maintenance)

---

## Decision Drivers

1. **Country availability** — Exchange must be legally accessible from Pakistan and/or UAE without a VPN
2. **API order placement actually enabled** — Some exchanges restrict retail futures order API access
3. **Testnet/demo** — Required for Phase 7 API mechanics testing
4. **Exchange-side SL/TP** — Attached to the entry order, mark-price triggered, survives app crash
5. **Reduce-only** — Required for safe position closing
6. **One-way position mode** — Required by risk config
7. **Isolated margin** — Required by risk config
8. **Taker fees** — Affects loss-at-stop calculation; lower is better at micro trade sizes
9. **API rate limits** — Must support the scheduler's polling frequency
10. **Minimum notional** — Must be compatible with max_notional_allowed = $6.00

---

## Candidates

Binance, Bybit, OKX, MEXC — all support USDT perpetual futures.

## MEXC Warning

Multiple community reports indicate that MEXC futures order placement API is disabled or restricted for retail accounts under the label "under maintenance." This must be verified via their official API documentation and a test account before selecting MEXC. If confirmed restricted, MEXC is eliminated as a candidate.

---

## Recommendation

**Bybit** or **OKX** are the primary candidates, pending feasibility results and owner confirmation of country availability. Both have testnet environments, reasonable fees, and documented exchange-side SL/TP support. Binance is a second choice if the Pakistan restriction is resolved. MEXC should only be selected if the order API is confirmed working on a real retail test account.

---

## Consequences

- Owner must verify account creation, KYC, and API order permissions in their country before Phase 1.
- The selected exchange determines which API endpoints are used in Phase 2 and Phase 7.
- If no exchange is accessible from PK/UAE with a working order API, the entire project is blocked at Phase 1.
- The feasibility script (`scripts/feasibility.py`) queries public endpoints from all four exchanges to compare min notional and tradability; the owner uses those results to make the final choice.

---

## Owner Action Required

1. Run the Phase 0 feasibility script and review `docs/specs/phase0-feasibility.md`.
2. Confirm which country you will primarily operate from (PK or UAE).
3. Create a test account on your preferred exchange and verify: account creation approved, KYC passed, API key can place a test futures order (use testnet if available).
4. Report the chosen exchange so Phase 1 can configure the adapter.
